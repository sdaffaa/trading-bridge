## ٣ · الحركة مكتوبة بنسبة من القيمة، لا بنقاط

كل شمعة بعد الرصيد مكتوبة بكسور من **U = POC − VAL** المقيسة، لا بنقاط مطلقة:

```js
const U = r2(POC - VAL);          // مقيسة من ملف الـ M15
const u = d => r2(VAL + d * U);
const EXC_D = 0.38;               // عمق التجاوز، كنسبة من U
```

فتصير الصفقة **متناسبة مع الملف الذي طلع فعلاً**، ويصير شيئان بنيويَّين بدل أن
يكونا حظاً: التجاوز أضحل من المسافة للـ POC، **ولا شيء قبل الدخول يتداول عند
الهدف**. المحاولة الأولى فشلت هنا بالضبط: كان `R = 1.08` والهدف مُلامَس قبل
الدخول بشمعة — فأُعيد بناء الشموع، لا الشروط.

## ٤ · السلّم: ما هو صادق فيه، وما هو موضوع

الصفوف **توضيحية ومكتوب على الشاشة أنها توضيحية** — الدلتا لا تُشتقّ من OHLC.
وما ليس توضيحياً:

| | |
|---|---|
| الدلتا | مجموع Ask − مجموع Bid = **−1280** |
| أثقل صف | يُحسب بالمجموع، لا يُختار |
| نسبة الامتصاص | Bid ÷ Ask عند ذلك الصف = **2.21** |
| **موضع الإغلاق** | **حقيقة شمعة**: `(c − l) ÷ (h − l)` = **0.703** — أغلقت قرب قمة المدى الذي حصل فيه البيع نفسه |

الامتصاص = بيع مبادر **قوي** + سعر **ما نزل**. الشرط الأول من السلّم والثاني من
الشمعة.
