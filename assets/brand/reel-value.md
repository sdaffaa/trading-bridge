# الدخول من حافة القيمة — ورقة التسجيل
### `reel-value.html` → `reel-value.mp4` · 1080×1920 · 29.80s · 30fps

الجزء الثالث. الجزء الثاني أُقفل على **«تعرف تحسب الستوب صح؟»**، وقاعدة الستوب
هنا هي الجواب — فاللوب اللي فتحه الريل السابق صار هوك هذا الريل.

**طريقة دخول جديدة بشروط مختلفة، على جارت مختلف كلياً.**

## ١ · النموذجان جنب بعض

| | نموذج السحب (الجزء ٢) | نموذج القيمة (هنا) |
|---|---|---|
| **الشرط الأول** | لازم اتجاه | لازم **رينج** — فلتر نظام سوق قبل أي شي |
| **الأداة** | هيكل + فجوة | Volume Profile: POC · VAH · VAL |
| **الحدث** | سحب سيولة فوق قمة | خروج فوق VAH **بلا قبول** |
| **الدخول** | من الفجوة | من الإغلاق اللي يرجع داخل القيمة |
| **الستوب** | فوق ظل السحب | فوق **قمة الخروج** |
| **الهدف** | السيولة المقابلة | هدفان: POC بعدين VAL |

> النقطة اللي تفرّق النموذج عن الكل: **الخروج يكون فوق حافة القيمة، مو فوق حافة
> الرينج.** بالمثال هنا قمة الخروج 105.80 وقمة الرينج 107.12 — يعني ما صار
> اختراق للرينج أصلاً. اللي يتداول اختراق الرينج ما شاف شي؛ واللي يقرأ منطقة
> القيمة شاف الصفقة كاملة.

## ٣ · الأرقام — كلها مقروءة، ولا واحد مكتوب

منطقة القيمة تطلع من `volumeProfile()` نفسه، والصفقة تُبنى عليها:

```js
ch.volumeProfile({ from: 0, to: 37, bins: 30, valueArea: 0.70, showVA: true });
const P = ch.profile;                      // ← المحرك يحسبها
const POC = P.poc, VAH = P.vah, VAL = P.val;

const ENTRY = C[44].c;                     // الإغلاق اللي رجع داخل القيمة
const STOP  = C[42].h;                     // قمة الخروج
const R1 = (ENTRY - POC) / (STOP - ENTRY);
const R2 = (ENTRY - VAL) / (STOP - ENTRY);
```

| | القيمة |
|---|---|
| POC | **100.78** |
| VAH · VAL | **104.50** · **97.49** |
| مدى الرينج | 93.99 – 107.12 |
| الدخول | **103.80** (إغلاق الشمعة ٤٤) |
| الستوب | **105.80** (قمة الشمعة ٤٢) — الخطر **2.00** |
| الهدف ١ · POC | **+1.51R** — وصل عند الشمعة ٤٩ |
| الهدف ٢ · VAL | **+3.15R** — وصل عند الشمعة ٥٥ |

**الشروط تحقّقت آلياً، لا بالعين:**

| الشرط | النتيجة |
|---|---|
| قمة الخروج فوق الـ VAH | ✓ 105.80 > 104.50 |
| الخروج داخل مدى الرينج (مو اختراق) | ✓ 105.80 < 107.12 |
| إغلاق الشمعة ٤٤ يرجع داخل منطقة القيمة | ✓ 97.49 < 103.80 < 104.50 |
| الستوب ما انلمس بعد الدخول | ✓ أعلى قمة بعد الدخول 104.10 |
| مخالفات الرسم | **صفر** |

**الهدفان ما يظهران إلا لما يوصل السعر لهما فعلاً** — عرض `+3.15R` من بداية الريل
يعلن نتيجة ما أنتجها الجارت بعد.

## ٤ · التصميم — وش تغيّر عن الجزأين السابقين

- **الشروط هي الواجهة، مو مفتاح تحت الجارت.** أربعة صناديق ٢×٢، كلها ظاهرة من
  الإطار صفر مطفية، وكل واحد يضيء لحظة ما يحققه الجارت فعلاً. النموذج فلتر قبل
  أن يكون دخولاً، فالشروط تستاهل نصف الشاشة.
- **الهستوغرام على يسار الجارت** بعرض ١٨٪ فقط: ملف الحجم يجب ألا يدفن الشموع
  اللي قِيس منها.
- **لونان لمفردتين:** القيمة كهرماني (`#E0A33C`) والهيكل سماوي. مفردتان على جارت
  واحد تحتاجان لونين، وإلا صار لازم تُشرح كل مرة.
- **صف الستوب** له سطر مستقل بحسابه ظاهراً `105.80 − 103.80 = 2.00` — هو الوعد
  اللي تركه الريل السابق مفتوحاً، وهو العملية الحسابية الوحيدة على الشاشة.
- **لا pan للجارت:** `barsVisible: 58` تخلي الرينج كله ثابتاً بالمشهد، لأن
  الهستوغرام مربوط ببداية الرينج ولو انزلق الجارت طلع برّه الشاشة.

## ٥ · أمانة الأداة

الملف مكتوب على الشاشة، ومكرّر هنا: **هذا ملف تعريف حجم مبني على مدى الشموع
(وقت عند السعر)، لا على حجم تِك ولا حجم منصّة.** الشكل والمنطق صحيحان، لكن
POC/VAH/VAL محسوبة من أين تحرّك السعر وكم بقي هناك — لا من كم عقد نُفِّذ.
على منصّة فيها حجم حقيقي، مرّر `volumes` للدالة وتصير القيم حقيقية.
